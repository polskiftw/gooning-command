# Gooning Command — DGD Guide

This is the canonical guide for the GitHub collector side of the project.

Do not combine these instructions with older versions of the project. This file describes the repository as it works now.

# 1. What this repository is

This repository is the backend collector.

It does four main jobs:

1. Checks configured Reddit sources.
2. Downloads new supported media.
3. Uploads that media to Cloudflare R2.
4. Updates the R2 gallery index and download-history database.

It is not the public website.

The public website is controlled by the separate Cloudflare Worker.

Use this rule:

```text
Getting content into R2 = GitHub repository
Showing content from R2 = Cloudflare Worker
```

# 2. Complete project flow

A scheduled GitHub Actions run does this:

```text
1. Start an Ubuntu GitHub runner.
2. Check out this repository.
3. Install Python, FFmpeg, and required Python packages.
4. Record and mask the runner's public IP.
5. Restore the prior gallery-dl archive database from R2.
6. Join the private Tailscale network.
7. Select the Flint 2 as the Tailscale exit node.
8. Verify that the public route changed to the home connection.
9. Prepare Reddit cookies and the gallery-dl configuration.
10. Scan every configured source.
11. Download supported new media to temporary GitHub runner storage.
12. Stop using the Flint 2 exit node.
13. Verify that GitHub's normal public route returned.
14. Upload downloaded media directly to R2.
15. Update gallery-index.json in R2.
16. Save the updated gallery-dl archive database to R2.
17. End the run.
```

Reddit and media downloads use the home route.

R2 uploads use GitHub's normal route.

The workflow refuses to contact Reddit if it cannot confirm that the home route is active. It also refuses to upload to R2 if it cannot confirm that the normal GitHub route returned.

# 3. Important repository files

## `app.py`

This is the main Python program.

It handles:

- Reading and validating `settings.json`.
- Decoding the Reddit cookies secret.
- Generating a temporary gallery-dl configuration.
- Running gallery-dl for each source.
- Tracking downloaded posts with a SQLite archive.
- Separating the download and upload phases.
- Uploading media to R2.
- Retrying interrupted R2 uploads.
- Updating `gallery-index.json`.
- Rolling back download history when an upload fails.
- Cleaning temporary files.

Do not edit this file for ordinary preference changes unless the setting does not already exist.

## `settings.json`

This contains normal collector settings.

This is where most ordinary preference changes belong.

## `.github/workflows/download-cats.yml`

This controls GitHub Actions.

It contains:

- The schedule.
- Job timeout.
- Dependency installation.
- Secret-to-environment mappings.
- Tailscale connection and exit-node routing.
- IP masking.
- The restore, download, and upload phases.
- Optional private source overrides.

## `requirements.txt`

This lists Python dependencies installed during each GitHub Actions run.

## `README.md`

This is the short front-page description shown by GitHub.

## `DGD.md`

This file. It is the canonical detailed guide.

# 4. Current schedule

The workflow schedule is stored in:

```text
.github/workflows/download-cats.yml
```

Current cron expression:

```text
3,18,33,48 * * * *
```

This asks GitHub to run at approximately:

```text
:03
:18
:33
:48
```

of every hour.

That is four scheduled runs per hour, approximately fifteen minutes apart.

GitHub Actions scheduled runs are not guaranteed to begin at the exact requested minute. GitHub may start them late.

The workflow also supports manual runs through the GitHub Actions page because `workflow_dispatch` is enabled.

# 5. Current `settings.json` settings

The exact setting names matter. Do not rename them casually.

## `sources`

Example shape:

```json
"sources": [
  "https://www.reddit.com/r/example1/new/",
  "https://www.reddit.com/r/example2/new/",
  "https://www.reddit.com/r/example3/new/"
]
```

Purpose:

- Lists the Reddit sources scanned in order.
- Each source should point to the subreddit's `/new/` listing.
- The workflow can privately override the first three entries with GitHub Secrets.

Current fallback behavior:

```text
REDDIT_SOURCE_1 exists → replace sources[0]
REDDIT_SOURCE_2 exists → replace sources[1]
REDDIT_SOURCE_3 exists → replace sources[2]
Secret missing or empty → keep the matching settings.json entry
```

## `browser_user_agent`

Purpose:

- Gives gallery-dl and yt-dlp an explicit browser identity.
- Must be one complete User-Agent string on one line.
- Must not contain placeholders.

Example shape:

```json
"browser_user_agent": "Mozilla/5.0 (...)"
```

## `posts_per_subreddit_per_scan`

Current value:

```json
"posts_per_subreddit_per_scan": 100
```

Purpose:

- Sets the maximum number of newest posts gallery-dl may examine for each source during one run.
- This is a post-range cap, not necessarily one Reddit request per post.
- A Reddit listing response can contain many posts in one JSON response.

The collector may stop before reaching 100 because of the archived-post stop setting.

## `reddit_request_delay_min_seconds`

Current value:

```json
"reddit_request_delay_min_seconds": 2
```

Purpose:

- Minimum random pause between page requests made by gallery-dl.

## `reddit_request_delay_max_seconds`

Current value:

```json
"reddit_request_delay_max_seconds": 4
```

Purpose:

- Maximum random pause between page requests made by gallery-dl.

Together, the current delay range is:

```text
2 to 4 seconds
```

## `stop_after_consecutive_archived_posts`

Current value:

```json
"stop_after_consecutive_archived_posts": 15
```

Purpose:

- Stops a source scan after gallery-dl encounters this many already-archived posts consecutively.
- Prevents every scheduled run from pointlessly checking the full 100-post window after the archive has caught up.

Example:

```text
Maximum scan window: 100 posts
Already-archived stop: 15 consecutive posts
```

If the newest 15 posts are all already archived, the source may finish quickly rather than checking all 100.

## `reddit_429_backoff_seconds`

Current value:

```json
"reddit_429_backoff_seconds": 60
```

Purpose:

- Tells gallery-dl how long to pause after Reddit returns HTTP 429 Too Many Requests before retry behavior continues.

## `allowed_extensions`

Current set:

```json
"allowed_extensions": [
  "jpg",
  "jpeg",
  "png",
  "gif",
  "webp",
  "mp4",
  "m4v",
  "webm"
]
```

Purpose:

- Only files with these extensions are eligible for R2 upload.
- Other downloaded file types are discarded.

## `r2_gallery_prefix`

Current value:

```json
"r2_gallery_prefix": "gallery/"
```

Purpose:

- Places uploaded media under the `gallery/` key prefix in R2.

Changing this may also require changes to the Cloudflare Worker if the Worker assumes a particular R2 layout.

## `maximum_file_size_mb`

Current value:

```json
"maximum_file_size_mb": 500
```

Purpose:

- Rejects files larger than this limit before upload.
- Also rejects zero-byte files.

## `download_retries`

Current value:

```json
"download_retries": 4
```

Purpose:

- Controls gallery-dl download retry attempts.

## `download_timeout_seconds`

Current value:

```json
"download_timeout_seconds": 45
```

Purpose:

- Controls the configured gallery-dl request timeout.

# 6. Required GitHub Secrets

Open the repository on GitHub and go to:

```text
Settings
→ Secrets and variables
→ Actions
```

The workflow expects these secrets.

## R2 secrets

```text
R2_ACCOUNT_ID
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
R2_BUCKET_NAME
```

Purpose:

- Allow the GitHub runner to restore history, upload media, update the index, and save history in R2.

## Tailscale secrets

```text
TS_OAUTH_CLIENT_ID
TS_OAUTH_SECRET
TS_EXIT_NODE_IP
```

Purpose:

- Join the private Tailscale network.
- Select the Flint 2 exit node.

## Reddit cookie secret

```text
REDDIT_COOKIES_BASE64
```

Purpose:

- Contains the entire Netscape-format Reddit cookies file encoded as one Base64 string.
- `app.py` decodes it into a temporary cookies file during the run.

Do not paste plain cookie text into this secret unless it has already been converted to the expected Base64 value.

# 7. Optional private source secrets

These are optional:

```text
REDDIT_SOURCE_1
REDDIT_SOURCE_2
REDDIT_SOURCE_3
```

Purpose:

- Keep chosen subreddit sources out of the committed configuration and mask matching values in GitHub Actions logs.

Accepted value format 1:

```text
example
```

Accepted value format 2:

```text
https://www.reddit.com/r/example/new/
```

Behavior:

```text
Secret contains a subreddit name
→ workflow converts it to https://www.reddit.com/r/<name>/new/

Secret contains a complete URL
→ workflow uses the URL directly

Secret does not exist or is empty
→ workflow leaves the matching settings.json source unchanged
```

The workflow works before these optional secrets are added because the current source URLs remain in `settings.json` as fallbacks.

After all three secrets have been added and verified, the public source values can be removed or replaced with neutral placeholders in a later update.

# 8. What GitHub masks

The workflow uses GitHub's `::add-mask::` command for detected public IP values.

It masks:

- The original GitHub runner public IP.
- The home-routed public IP detected after enabling the Tailscale exit node.
- The public IP detected after returning to GitHub's direct route.
- Optional private source secret values used by the workflow.

GitHub also masks registered GitHub Secret values when exact matching values appear in logs.

Masking reduces accidental exposure in logs. It does not remove values already committed to public repository files or old commit history.

# 9. Restore, download, and upload modes

`app.py` supports these modes through the `APP_MODE` environment variable.

## `restore`

Used before Tailscale routing begins.

It:

- Connects directly to R2.
- Downloads the prior gallery-dl archive database if it exists.

## `download`

Used while the Flint 2 exit node is active.

It:

- Decodes Reddit cookies.
- Builds the gallery-dl configuration.
- Scans all sources.
- Downloads media into temporary storage.
- Saves a temporary run-state file.
- Does not upload media to R2.

## `upload`

Used after the normal GitHub route returns.

It:

- Reads the temporary run-state file.
- Uploads valid media to R2.
- Updates `gallery-index.json`.
- Saves the archive database to R2.
- Rolls history back when uploads fail so uncertain files can be retried later.

## `full`

Local/manual fallback mode.

It performs restore, download, and upload in one invocation.

GitHub Actions should continue using the three separate phases.

# 10. Download history and duplicate prevention

The collector uses gallery-dl's SQLite archive database.

Current R2 history key:

```text
_internal/gallery-dl-archive-v0.2.1.sqlite3
```

The archive records media already processed by gallery-dl.

The archive is restored before downloading and saved after uploading.

If an R2 media upload fails, the program rolls the archive back far enough to retry uncertain files on the next run.

The R2 gallery index also prevents uploading an object key already listed in the index.

This is download-history and object-key duplicate prevention. It is not a full perceptual image-duplicate detector.

# 11. R2 gallery index

Current index key:

```text
gallery-index.json
```

The collector stores an object with this general shape:

```json
{
  "version": 1,
  "generated_at": 1234567890,
  "count": 123,
  "items": [
    {
      "key": "gallery/example-file.jpg",
      "ext": "jpg",
      "size": 123456
    }
  ]
}
```

The Cloudflare Worker reads this index to know which objects exist and what it can show on the website.

Changing this structure may require matching changes in the Worker.

# 12. What belongs in GitHub versus Cloudflare

## Make the change in this GitHub repository when it affects:

- Which subreddits are scanned.
- Number of posts checked.
- Archived-post stopping behavior.
- Reddit request delay or 429 backoff.
- Reddit cookies or User-Agent handling.
- Supported download hosts.
- Download retries or timeout.
- Allowed extensions.
- Maximum accepted file size.
- R2 upload behavior.
- R2 key layout or index generation.
- GitHub Actions schedule.
- Tailscale routing.
- IP masking in GitHub logs.
- GitHub Secrets.

## Make the change in the Cloudflare Worker when it affects:

- What appears when the website loads.
- Page layout, buttons, colors, fonts, or error pages.
- Previous, next, random, fullscreen, fit, or auto-next behavior.
- Keyboard shortcuts.
- Website routes.
- `robots.txt` served by the site.
- Website security or cache headers.
- Reading or serving R2 files to visitors.
- Video range requests and browser playback.
- Public gallery APIs.

## A change may require both when it affects:

- R2 folder names.
- `gallery-index.json` structure.
- New metadata written by GitHub and displayed by the Worker.
- New media categories that require both collection and viewer support.

# 13. How to change an ordinary setting

Example: change the per-source post cap.

1. Open `settings.json`.
2. Find:

```json
"posts_per_subreddit_per_scan": 100
```

3. Replace only the number.
4. Commit the change to `main`.
5. The next scheduled run will use it automatically.

No Cloudflare Worker deployment is needed for this type of change.

# 14. How to change the GitHub Actions schedule

1. Open:

```text
.github/workflows/download-cats.yml
```

2. Find the `schedule` section near the top.
3. Change the cron expression.
4. Commit the change to `main`.

The new schedule applies to future GitHub Actions scheduling.

GitHub may still start scheduled runs late.

# 15. How to add private subreddit source secrets

For each source:

1. Open the repository on GitHub.
2. Open `Settings`.
3. Open `Secrets and variables`.
4. Open `Actions`.
5. Choose `New repository secret`.
6. Use one exact name:

```text
REDDIT_SOURCE_1
REDDIT_SOURCE_2
REDDIT_SOURCE_3
```

7. Paste either the subreddit name or complete `/new/` URL as the value.
8. Save the secret.

Do not put quotation marks around the value.

You may add the three secrets one at a time. Missing secrets continue using the matching public fallback entries.

# 16. Healthy run indicators

A healthy run should show behavior like:

```text
Restored prior download history from R2
Home routing is active
Scanning source
Download phase complete
Direct GitHub routing is restored
Uploaded ... -> r2://...
Updated gallery-index.json
Saved download history to R2
Direct R2 upload phase complete
```

The final upload summary reports:

```text
Downloaded files examined
Files uploaded
Uploads failed
```

A clean run should normally end with zero failed uploads.

# 17. Important failure behavior

## Home route does not activate

The workflow stops before contacting Reddit.

## GitHub direct route does not return

The workflow stops before uploading to R2.

## One source partially fails

Files already downloaded may still continue to the upload phase.

## R2 upload fails

The program retries the transfer.

If it still fails:

- The scan continues.
- The failure is counted.
- Download history is rolled back far enough to retry uncertain media later.

## No prior history exists

This is normal on the first run.
