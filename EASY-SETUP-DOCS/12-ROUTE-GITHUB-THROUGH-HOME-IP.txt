DGD 12 — MAKE GITHUB USE YOUR HOME IP
======================================

WHAT THIS DOES
--------------
Every GitHub run will:

1. Start on GitHub's temporary computer.
2. Join your Tailscale network.
3. Select your Flint 2 as the exit node.
4. Confirm that the public IP changed.
5. ONLY THEN contact Reddit and upload to R2.

If Tailscale does not work, the job STOPS. It will not quietly use GitHub's IP.


PART A — APPROVE THE FLINT 2 AS AN EXIT NODE
---------------------------------------------
You already turned on Run Exit Node in the Flint 2.

Now open:

https://login.tailscale.com/admin/machines

Find the Flint 2.
Click its three-dot menu.
Click Edit route settings.
Turn on Use as exit node.
Save.

Also use the three-dot menu and choose Disable key expiry for the Flint 2.


PART B — ADD THE GITHUB-ACTIONS TAG AND PERMISSION
---------------------------------------------------
Open:

https://login.tailscale.com/admin/acls

You must allow devices tagged tag:github-actions to use an exit node.

DO NOT erase unrelated rules already in the file.

Your policy needs these two pieces:

1. Inside tagOwners:

"tag:github-actions": ["autogroup:admin"]

2. Inside grants, add this grant:

{
  "src": ["tag:github-actions"],
  "dst": ["autogroup:internet"],
  "ip": ["*"]
}

If this is a brand-new/simple policy and you have nothing important there, a complete tiny example is:

{
  "tagOwners": {
    "tag:github-actions": ["autogroup:admin"]
  },
  "grants": [
    {
      "src": ["tag:github-actions"],
      "dst": ["autogroup:internet"],
      "ip": ["*"]
    }
  ]
}

Click Save.


PART C — CREATE THE TAILSCALE OAUTH CLIENT
-------------------------------------------
Open the Tailscale admin console.
Go to Settings.
Open OAuth clients.
Click Generate OAuth client.

Description/name:

gooning-party-github

Turn on the auth_keys scope.
For the tag, choose or enter:

tag:github-actions

Create the client.

Tailscale will show TWO values:

OAuth Client ID
OAuth Client Secret

Keep that page open until both are saved. The secret may not be shown again.


PART D — THE THREE TAILSCALE SECRETS
--------------------------------------------------
Open your GitHub repository.

Settings
→ Secrets and variables
→ Actions
→ Repository secrets

Add these THREE secrets one at a time:

NAME: TS_OAUTH_CLIENT_ID
VALUE: paste the Tailscale OAuth Client ID

NAME: TS_OAUTH_SECRET
VALUE: paste the Tailscale OAuth Client Secret

NAME: TS_EXIT_NODE_IP
VALUE: 100.124.207.6

The 100.124.207.6 value is the Router Virtual IP shown by your Flint 2.
Do not put spaces before or after it.

These are secrets 6, 7, and 8 in DGD 03. After adding them, GitHub must show eight repository secrets total.


PART E — REPLACE THE GITHUB WORKFLOW FILE
------------------------------------------
From this v0.2.4 package, open:

.github\workflows\download-cats.yml

Replace the existing GitHub file at:

.github/workflows/download-cats.yml

Commit the change.

You do NOT need to replace app.py again if GitHub already has v0.2.3.
You do NOT need to change the Worker.


PART F — RUN IT
---------------
Go to GitHub → Actions → Download cats to R2.
Click Run workflow.

The run should show these new steps:

Remember GitHub runner public IP
Join private Tailscale network
Force all traffic through the Flint 2

The third step prints:

GitHub runner public IP before Tailscale: ...
Public IP after selecting the Flint 2: ...
Exit-node routing is active.

The two IPs MUST be different.

If the Tailscale step fails, do not panic. Open the failed step and use the exact error in DGD 08 troubleshooting.


IMPORTANT SECRET-NAME CHECK
---------------------------
The exit-node secret must be named exactly:

TS_EXIT_NODE_IP

Do not name it TAILSCALE_EXIT_NODE. The workflow will not read that name.
For one complete list of all eight secrets, open:

03-ADD-ALL-EIGHT-GITHUB-SECRETS.txt
